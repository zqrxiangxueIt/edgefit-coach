# 演示视频叙事策略 v2（策略顾问稿，未改动 demo_video_plan.md）

> 依据：demo 调研（Devpost 评审指引 / hackathon 评审 rubric / 边缘 CV demo 惯例）+ 本仓库已交付功能审计。
> 结论先行：**问题开场 + 35 秒内"aha 时刻" + 三类纠错失败瞬间 + 结尾数据复盘卡**，总时长压在 3:05~3:20。

---

## 1. 调研要点（对我们直接适用的）

| 来源结论 | 对本片的含义 |
|---|---|
| 评审在**前 30~45 秒**决定印象；不要用设备巡礼/片头开场（Devpost/SaaS demo 惯例） | 现脚本分镜 1"设备全家福"应取消独立镜头，硬件作为**问题画面的背景**自然入镜 |
| 结构模板 Problem → Solution → Live demo → **Results**；3 分钟是甜点区间 | 现脚本缺少"Results 收束"镜头——数据散在各模式里，结尾只有一句口号 |
| 评审最记住了两样东西：**真实输入跑起来的工作品** + **可核验的量化结果**（mapdevents/scorejudge rubric：working demo + technical execution 权重最高） | 弯举计数必须有真人+真哑铃（已有）；结尾要有一张"数字卡"汇总 -98.6% / 5.6ms / 21ms |
| **失败/对抗瞬间提升可信度**：故意做错→系统当场抓住，比全对更可信；且是记忆点 | 现脚本只有 2 类错误（半程/摆动）。仓库已实现但**脚本没演**的：幽灵计数拦截（`suppressed` 面板项）、训练计划状态机（3-2-1 倒计时大字、组间休息） |
| CV/边缘 demo 惯例：画面角落常驻 **FPS / 延迟 / 模型名 HUD**，并区分"纯推理 vs 端到端"口径 | 仪表盘三张图已够；台词要**念出**"这是采集到收帧的全链路，不含摄像头缓冲"式的诚实口径（benchmarks.md 已有此口径） |
| 假设评审在小屏/静音环境看：关键数字要**大字上屏**（字幕卡），不要只靠旁白 | 每个模式切换后打一张 1.5s 的数据字幕卡 |

## 2. 现脚本（7 分镜）诊断

| 现分镜 | 判定 | 理由 |
|---|---|---|
| 1 设备全家福 20s | **改** | 等价于"logo 开场"；硬件并入分镜 2 背景，省 15s |
| 2 raw 浪费 15s | **保留并升级为开场钩子** | 问题开场正是调研推荐；台词改成"挑衅式" |
| 3 event 省流 15s | 保留 | aha 时刻之一 |
| 4 cascade 静默 20s | 保留 | "端侧 NN 决定发不发"是技术叙事核心 |
| 5 privacy 黑帧 20s | 保留 | 隐私=记忆点，黑帧画面极强 |
| 6 弯举计数纠错 60s | **扩充到 70s** | 加入第三类错误（节奏）+ 幽灵计数拦截 + TTS 出声 |
| 7 收尾 20s | **改为数据复盘卡 + 一键关停** | 补上"Results"环节 |

**缺失桥段**（仓库已实现、脚本未用）：训练计划 3-2-1 倒计时/组间休息大字覆盖层（`server/session.py`，画面表现力极强）、`⏻` 一键开关整系统（`server/power.py`，"工程完成度"的证明）、事件日志逐次 min 角度记录。

## 3. 增强功能评估矩阵（要不要为视频加功能）

| 功能 | 演示价值 | 实现成本 | 风险 | 结论 |
|---|---|---|---|---|
| **TTS 语音教练**（浏览器 `SpeechSynthesis`，dashboard JS 即可，服务端零改动） | 高——"AI 教练"第一次开口说话，听觉记忆点；警告+报数出声 | 低（~30 行 JS；rep 事件与 warnings 已推送到前端） | 中文语音因浏览器而异（Edge 最好）；与旁白冲突 | **加**。只在弯举段出声，其他段静音；先在拍摄机验收 zh-CN 语音 |
| **节奏反馈"下放过快"**（RepEvent 已含 `t`，逐次时长/间隔 vs 阈值 → warning） | 中高——纠错从 2 类变 3 类（幅度/借力/节奏），"教练感"质变 | 低（curl_counter 或 pipeline 加一个逐次间隔检查 + 一条 warning 文案） | 阈值需排练校准，避免误报 | **加**，作为弯举段第三类故意错误 |
| **ROM 逐次图表**（事件日志已有逐次 min 角度；chart.js 已引入） | 中——"数字教练记得你每一次"的可视化 | 低（一张 bar chart，rep 索引 × min_angle） | 无 | **加**，但放在**组间休息/复盘卡**里展示，不打断动作段 |
| **"超越上次"横幅** | 中——情感 payoff，但跨会话历史需要持久化，拍出来容易像摆拍 | 同会话版=零成本：`session.set_reps` 已存每组次数，第 2 组完成时对比第 1 组弹横幅（纯前端） | 跨会话版要 localStorage/落盘，拍前要"造历史"，可信度反而降 | **只做同会话版**："第 2 组 9 > 第 1 组 8"；跨会话版不上片 |

## 4. 最终推荐分镜表 v2（总 3:05，硬上限 3:30）

| # | 时间轴 | 时长 | 画面/动作 | 一句话台词（上字幕） |
|---|---|---|---|---|
| 1 | 0:00–0:15 | 15s | 问题开场：人在垫上持哑铃，画面同框 Pi5+摄像头+屏幕；点 raw，走出画面，带宽曲线仍在 ~1.2MB/s 跳 | "这台摄像头不懂省——画面里没人，它还在每秒传 1.2 兆。" |
| 2 | 0:15–0:35 | 20s | 点 event，静止 3 秒曲线塌到个位数；一做动作立刻回弹 | "会算的摄像头只在**你动的时候**说话——静止时段带宽 -98%。"（打字幕卡：-98%） |
| 3 | 0:35–0:55 | 20s | 点 cascade，走出画面→彻底静默（1fps 心跳）；走回→瞬间 30fps | "树莓派上的神经网络替链路做决定：这帧，值得发吗？"（字幕卡：端侧检测 21ms/帧） |
| 4 | 0:55–1:15 | 20s | 点 privacy，出画=黑帧，入画=只剩人形 ROI | "隐私模式下，你的房间**从不上传**。" |
| 5 | 1:15–1:25 | 10s | 转场：屏幕上点"开始训练"，3-2-1 倒计时大字 | "省下来的带宽，换一个真教练。" |
| 6 | 1:25–2:35 | 70s | **核心秀**：连续 8~10 个标准弯举（计数跳动、相位 HUD、TTS 报数）；随后依次故意：①半程→"幅度不足" ②甩躯干→"躯干摆动" ③快放→"下放过快"（各出警告+TTS）；最后垂臂静止触发一次**幽灵计数被拦截**（suppressed +1） | "它不只数数——幅度、借力、节奏，错一次抓一次；连检测器的幻觉都骗不过它。" |
| 7 | 2:35–2:50 | 15s | Results：组间休息/完成卡（本次各组次数、ROM 逐次柱状图、"第 2 组 > 第 1 组"横幅），角落 e2e/推理延迟 HUD | "每一项数字都来自真实跨机链路实测：全链路 46ms，端侧检测 21ms。" |
| 8 | 2:50–3:05 | 15s | 收尾：点 ⏻ 一键关停整系统（Pi 流+管线全黑），定格标题卡 | "边缘初步计算 + 端侧神经网络：低带宽、隐私友好、实时——Working code, not hype." |

**时长控制**：超 3:20 的删减顺序——① 分镜 2 压到 12s（event 与 cascade 保留 cascade）→ ② 核心秀压到 60s（每类错误各做 1 次）→ ③ 分镜 5 倒计时只留 "1" 半秒。**不删**：错误三连、幽灵拦截、数据卡（调研表明这些才是记忆点）。

## 5. 拍摄检查清单 v2（实操）

**机位与画面**
- [ ] 主机位手机横屏 1080p/4K、三脚架固定，L 形布局同框：人（半身，占画面高 ≥1/2）+ Pi5+摄像头 + 显示器
- [ ] 侧面 45°~90°：**90° 正侧**时肘角最利于姿态估计，拍摄与识别双赢；确认手腕/肩/髋全程可见
- [ ] **屏幕单独用 OBS 60fps 录屏**作画中画素材（防频闪、防摩尔纹的根治方案）；主机位拍屏仅作备用
- [ ] 拍屏备用时的防频闪：屏幕 60Hz → 快门锁 **1/60 或 1/120**（禁 1/50）；屏幕调到最亮、机位侧倾 5~10° 避摩尔纹；**先拍 10s 试片回看**再正式开拍
- [ ] 曝光/白平衡/对焦三锁（AE/AF/AWB lock），人走动时画面不抽动

**光线与声音**
- [ ] 主光 45° 打人，人背后无窗（屏幕不逆光）；夜间顶灯全开
- [ ] 领夹麦或手机近距收音；TTS 段落确认系统外放可闻；开拍前录 10s 环境底噪
- [ ] TTS 与旁白不同段出现（分镜 6 出声，其余静音），后期不需要压轨

**系统准备（开拍前 30 分钟）**
- [ ] `bash scripts/stop_system.bat` 先清理残留进程/释放摄像头，再 `start_system.bat` 走 ⏻ 按钮流程（这也是分镜 8 的彩排）
- [ ] 浏览器：全新配置文件、隐藏书签栏、100% 缩放、全屏 F11；Windows 专注助手开（弹窗=废片）；确认仪表盘"● 已连接"
- [ ] Pi 与笔记本都插电；Tailscale 连通性预检；关闭系统自动更新
- [ ] 新功能先在拍摄机上验收：TTS zh-CN 语音存在且不卡、节奏警告阈值排练过（找队友先做 20 个弯举标定）
- [ ] 若加了 ROM 图/横幅：确认图表在 1080p 录屏里可读（字号 ≥12px）

**拍摄纪律**
- [ ] **先拍分镜 6（核心秀）**——返工率最高；模式切换段（2/3/4）最后拍，一次过
- [ ] 每个动作前后各留 3s 余量；模式切换鼠标放慢，切完**停 2 秒**看曲线；每次报数后自然停顿
- [ ] 每条素材结尾报板（"分镜 X 第 N 条"）；备一块写好台词卡的提词板放在镜头旁
- [ ] 双保险：OBS 全程录屏与主机位同时录制，现场回放核对关键数字（-98%、计数、警告文案）再拆机

## 6. 字幕/口播原则

- 关键数字只说一遍、同时大字上屏（-98.6% / 21ms / 46ms / 5.6ms）
- 口径诚实（与 benchmarks.md 一致）："全链路=采集→PC 收到，不含摄像头缓冲"；cascade 空场景说"≈0"而不是绝对 0
- 每个镜头一句话台词，宁短勿长；收尾句固定为 "Working code, not hype."
